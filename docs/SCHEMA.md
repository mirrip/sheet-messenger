# Структура данных

## Users

| Поле | Назначение |
| --- | --- |
| `user_id` | Неизменяемый внутренний ID пользователя |
| `username` | Уникальное публичное имя для поиска |
| `username_key` | Нормализованный username для проверки уникальности |
| `password_hash` | HMAC-хэш пароля |
| `password_salt` | Индивидуальная соль пароля |
| `phone` | Неподтверждённый изменяемый телефон |
| `status` | `active` или состояние блокировки |
| `created_at` | Дата регистрации |
| `updated_at` | Дата изменения профиля |
| `last_login_at` | Последний успешный вход |
| `last_message_at_ms` | Метка строгого ограничения одного сообщения в секунду |

## Devices

Каждый вход создаёт отдельный `device_id` и случайный токен сессии. В таблице хранится только `session_hash`. Сессия действует 180 дней и может быть отозвана. В поле `push_token` хранится Firebase Installation ID (историческое имя столбца), а `is_primary` определяет единственное устройство аккаунта для push.

## Messages

Содержимое сообщения занимает два основных поля:

- `message_type`: `text`, `photo` или `video`;
- `content_json`: текст либо ссылка/ID медиа, MIME-тип, размер, превью и подпись.

Служебные поля содержат последовательность, ID сообщения, чат, отправителя, получателя личного сообщения, ответ на другое сообщение и даты изменения/удаления. Сами фото и видео в ячейки таблицы не помещаются.

Личный `chat_id` вычисляется сервером из двух внутренних ID. Общий канал имеет ID `general`; push из него не отправляется.
