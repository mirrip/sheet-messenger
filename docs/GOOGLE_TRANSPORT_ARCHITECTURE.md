# Архитектура транспорта «кумир»: Google Apps Script + Google Sheets

Статус документа: спецификация следующего этапа. На текущем этапе таблицы и Apps Script не создаются.

## 1. Основные правила

- До успешного входа клиент не запрашивает чаты, сообщения, группы, каналы, профили других пользователей или медиа.
- Регистрация выполняет только `auth.register`: создаёт аккаунт и пустой профиль. После регистрации клиент не запрашивает переписки автоматически.
- После входа клиент сначала получает краткий список доступных переписок, затем загружает сообщения только выбранной переписки.
- Любой запрос сообщений содержит `conversation_id`; сервер проверяет действующую сессию и членство пользователя именно в этой переписке.
- Сообщения одной переписки никогда не выбираются по имени пользователя, части строки или совпадению участников. Единственный ключ разделения — неизменяемый `conversation_id`.
- Контакты находятся только в IndexedDB/localStorage конкретного устройства и никогда не отправляются в Google Apps Script.
- Пользователи и профили хранятся до явного удаления аккаунта. Группы и каналы хранятся, пока в них есть хотя бы один активный участник.
- Обычные сообщения и связанное с ними медиа хранятся 10 суток с момента `created_at`.
- Все даты передаются в UTC в ISO 8601, а ежедневное обслуживание запускается в часовом поясе `Europe/Moscow`.

## 2. Разделение данных по таблицам

Рекомендуется использовать отдельные Google-таблицы, а не листы одного огромного файла.

### 2.1 Auth Database

Лист `Users`:

| Поле | Назначение |
| --- | --- |
| `user_id` | UUID пользователя, неизменяемый первичный ключ |
| `username_key` | нормализованный уникальный username в нижнем регистре |
| `password_hash` | результат PBKDF2/Scrypt/Argon2 на доверенном сервере; открытый пароль не хранится |
| `password_salt` | уникальная соль |
| `password_version` | версия алгоритма для будущей миграции |
| `status` | `active`, `blocked`, `deleted` |
| `created_at`, `updated_at`, `last_login_at` | служебные даты |

Лист `Sessions`:

| Поле | Назначение |
| --- | --- |
| `session_id_hash` | хеш непрозрачного токена сессии |
| `user_id` | владелец сессии |
| `device_id` | локальный UUID установки |
| `created_at`, `expires_at`, `revoked_at` | жизненный цикл сессии |

### 2.2 Profile Database

Лист `Profiles`:

`user_id`, `display_name`, `phone`, `bio`, `current_photo_id`, `created_at`, `updated_at`.

Лист `ProfilePhotos`:

`photo_id`, `user_id`, `storage_file_id`, `mime_type`, `size_bytes`, `sha256`, `position`, `created_at`, `deleted_at`.

Профиль и его фотографии не имеют автоматического срока удаления. Удаление выполняется только владельцем аккаунта.

### 2.3 Conversations Database

Лист `Conversations`:

| Поле | Назначение |
| --- | --- |
| `conversation_id` | UUID переписки |
| `type` | `dm`, `group`, `channel`, `saved` |
| `dm_key` | только для личного диалога: два `user_id`, отсортированные и соединённые двоеточием |
| `title`, `username_key`, `photo_id` | оформление группы/канала |
| `owner_user_id` | владелец группы/канала |
| `status` | `active`, `archived`, `deleted` |
| `last_message_seq`, `last_message_at` | быстрый список чатов и курсор |
| `created_at`, `updated_at` | служебные даты |

Лист `ConversationMembers`:

`conversation_id`, `user_id`, `role`, `joined_at`, `left_at`, `last_read_seq`, `cleared_before_seq`, `muted_until`, `status`.

Уникальный составной ключ: `conversation_id + user_id`. Для канала роли: `owner`, `admin`, `subscriber`; для группы: `owner`, `admin`, `member`.

### 2.4 Messages Database

Сообщения делятся на месячные листы `Messages_YYYY_MM`. Это предотвращает постоянное сканирование одного бесконечного листа.

| Поле | Назначение |
| --- | --- |
| `message_id` | UUID сообщения |
| `conversation_id` | строгая принадлежность чату |
| `seq` | возрастающий номер внутри этой переписки |
| `sender_user_id` | автор |
| `kind` | `text`, `file`, `voice`, `video_note`, `system` |
| `text` | текст или пустая строка |
| `reply_to_message_id` | ответ на сообщение |
| `forwarded_from_message_id` | источник пересылки без раскрытия чужой переписки |
| `created_at`, `edited_at`, `deleted_at` | жизненный цикл |
| `expires_at` | `created_at + 10 суток` |

Лист `MessageMedia`:

`media_id`, `message_id`, `storage_file_id`, `original_name`, `mime_type`, `size_bytes`, `sha256`, `created_at`, `expires_at`, `deleted_at`.

Файл хранится без перекодирования. До публикации сообщения сервер сверяет размер и SHA-256; получатель после загрузки может повторно проверить SHA-256. Медиа сообщения удаляется вместе с сообщением после 10 суток. Фото профиля находится в отдельном бессрочном хранилище.

Лист `MessageReactions`:

`conversation_id`, `message_id`, `user_id`, `emoji`, `created_at`. Реакции удаляются вместе с сообщением.

## 3. Серверные модули Apps Script

- `Router.gs` — принимает только известные команды, проверяет схему запроса, выдаёт единый JSON-конверт.
- `AuthService.gs` — регистрация, вход, выход и проверка сессии. Не возвращает пароль, соль или хеш.
- `ProfileService.gs` — собственный профиль и публичная часть профиля другого пользователя.
- `ConversationService.gs` — список переписок, создание DM/группы/канала, членство и права.
- `MessageService.gs` — страницы сообщений одной переписки, отправка, изменение, удаление, реакции и пересылка.
- `MediaService.gs` — создание загрузки, проверка частей, фиксация файла, контроль хеша и выдача короткоживущего доступа.
- `RetentionService.gs` — пакетное удаление просроченных сообщений, реакций и медиа.
- `IndexService.gs` — точные индексы `username_key`, `dm_key`, `conversation_id`, `message_id` и курсоров.
- `LockService.gs` — `LockService` вокруг регистрации, выделения `seq` и изменения членства.
- `AuditService.gs` — технические ошибки и события безопасности без текста сообщений и паролей.

### 3.1 Точный комплект для создания

Создаётся **один проект Google Apps Script**, а не отдельный проект для каждого сервиса. В нём будет 14 файлов `.gs`:

1. `Config.gs`
2. `Setup.gs`
3. `Router.gs`
4. `Validation.gs`
5. `AuthService.gs`
6. `SessionService.gs`
7. `ProfileService.gs`
8. `ConversationService.gs`
9. `MessageService.gs`
10. `MediaService.gs`
11. `RetentionService.gs`
12. `IndexService.gs`
13. `LockService.gs`
14. `AuditService.gs`

Дополнительно используется стандартный манифест `appsscript.json`. Итого в редакторе будет 15 файлов: 14 файлов кода и один манифест. Публикуется одно веб-приложение и создаётся один ежедневный триггер очистки.

Создаются **четыре файла Google Таблиц** и десять начальных листов:

1. `Messenger Auth` — `Users`, `Sessions`.
2. `Messenger Profiles` — `Profiles`, `ProfilePhotos`.
3. `Messenger Conversations` — `Conversations`, `ConversationMembers`.
4. `Messenger Messages` — текущий `Messages_YYYY_MM`, `MessageMedia`, `MessageReactions`, `RetentionQueue`.

Новые месячные листы `Messages_YYYY_MM` создаются автоматически и не требуют ручной регистрации.

## 4. API-контракт

Каждый ответ:

```json
{
  "ok": true,
  "request_id": "uuid",
  "data": {},
  "error": null
}
```

После входа каждый закрытый запрос содержит `session_token`, `device_id`, `request_id`. Для повторяемых операций отправки используется `idempotency_key`, поэтому сетевой повтор не создаёт дубль.

Команды:

- `auth.register` — создаёт пользователя и пустой профиль; чаты не читает.
- `auth.login` — проверяет пароль, возвращает сессию и собственный профиль; сообщения не читает.
- `conversations.list` — возвращает только переписки, где пользователь является активным участником, и только краткое последнее событие.
- `messages.page` — принимает один `conversation_id`, `before_seq` и `limit`; проверяет членство до чтения.
- `messages.sync` — принимает один `conversation_id` и `after_seq`; никогда не возвращает события другого чата.
- `messages.send`, `messages.edit`, `messages.delete`, `messages.forward`, `reactions.toggle` — проверяют сессию, членство, права и совпадение автора там, где это требуется.
- `conversations.clearForMe` — обновляет только `cleared_before_seq` текущего участника; чужая история физически не удаляется раньше общего срока хранения.
- `profile.get`, `profile.update`, `profile.photos.*` — отдельные операции профиля.
- `spaces.create`, `spaces.update`, `spaces.members.*` — группы и каналы.

## 5. Потоки клиента

### Вход

1. `auth.login`.
2. При успехе сохранить сессию в защищённом локальном хранилище.
3. `conversations.list`.
4. Не открывать произвольный старый `conversation_id` из другой сессии.
5. При выборе чата — `messages.page` только для выбранного `conversation_id`.

### Регистрация

1. `auth.register`.
2. Показать пустой интерфейс аккаунта.
3. Не вызывать `conversations.list` и `messages.*`, пока пользователь сам не начнёт работу либо не выполнит последующий вход.

### Переключение чатов

1. Отменить предыдущий запрос через `AbortController`.
2. Увеличить локальное поколение рендера.
3. Запросить сообщения нового `conversation_id`.
4. Применить ответ только если его `conversation_id` и поколение всё ещё совпадают с открытым чатом.

### Изменение и удаление

- Изменять можно только собственное текстовое сообщение.
- Удалять можно только собственное сообщение, если пользователь не имеет отдельного права модератора.
- Сервер обновляет запись по паре `conversation_id + message_id`; одного `message_id` недостаточно.

## 6. Очистка каждые сутки

Устанавливается один time-driven trigger `RetentionService.runDaily` около 00:00 по Москве.

Алгоритм:

1. Выбрать строки с `expires_at <= now` пакетами, например по 500.
2. Пометить сообщения удалёнными и собрать их `message_id`.
3. Удалить связанные реакции и файлы Google Drive.
4. Удалить строки или перенести их в технический карантин не более чем на один цикл.
5. Обновить `last_message_seq/at` затронутых переписок.
6. Продолжать пакетами в следующих запусках, если приближается лимит времени Apps Script.

Профили эта задача не удаляет. Пустые группы и каналы удаляются отдельной операцией изменения состава, а не задачей десятидневной очистки.

## 7. Производительность и пределы Google Sheets

- Не выполнять полный поиск по всем сообщениям при каждом открытии приложения.
- Использовать месячные листы, индекс переписок и пагинацию по `seq`.
- Читать и писать диапазоны пакетами через `getValues/setValues`, а не по одной ячейке.
- Кэшировать только несекретные индексы через `CacheService`; авторизацию всегда проверять по источнику истины.
- Большие бинарные файлы не кодировать целиком в Base64 и не помещать в ячейки. Для них нужен отдельный поток загрузки в хранилище с проверкой SHA-256.

## 8. Удаление пустой группы или канала

После выхода или удаления участника сервер под блокировкой пересчитывает только активные записи `ConversationMembers` данной переписки. Если их стало ноль:

1. группа или канал помечается `deleted` и перестаёт возвращаться любым клиентским запросом;
2. записи состава и приглашения удаляются;
3. сообщения, реакции и медиа этой группы или канала ставятся в очередь немедленной каскадной очистки;
4. повторный запрос с тем же `idempotency_key` не создаёт объект повторно и не вызывает ошибку.

При одном или большем числе активных участников группа или канал автоматически не удаляется. Личная переписка (`dm`) этим правилом не затрагивается.
